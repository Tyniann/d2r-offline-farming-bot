Was nextStep heute wirklich ist

internal/tasks/pipeline_flow.go Funktion (*runPipeline) nextStep ist eine reine Nachfolgerfunktion von etwa 200 Zeilen. Sie entscheidet nicht über Combat, Loot-Auswahl, Timeouts oder Input. Sie beantwortet nur: welcher Step-Name folgt auf den aktuellen, gegeben Phase und wenige Flags.

4. Getroffene Entscheidung

Verbindliche Lage

Stage D bleibt bedingt und nicht verworfen. Ein Oracle-Doppel der alten nextStep-Funktion ist derzeit nicht sinnvoll. Der nächste sinnvolle Schritt ist die Characterization-Matrix (Stufe 0). Kettenextraktion (Stufe 1) nur bei nachgewiesenem Bedarf. Ein Tabellen- oder Graphresolver (Stufe 2) bleibt gesperrt, bis ein konkreter Topologieanlass und ein ausdrücklicher Auftrag vorliegen.

Warum kein Oracle jetztEs gibt keine zweite Implementierung, die verglichen werden müsste. Ein eingefrorenes nextStepLegacy verdoppelt jede spätere legitime Topologieänderung und driftet. Die Goldens von Stufe 0 sind die erwartete Topologie.
Warum zuerst Stufe 0Sie ändert kein Produktionsverhalten, schließt die nachgewiesene Testlücke und ist Voraussetzung für Stufe 1 und 2. Ohne Matrix wäre jede Extraktion oder Tabelle blind.
Warum Stufe 1 nur bei BedarfVier identische Teilsequenzen lassen sich später als benannte Helfer ziehen. Das ist der größte Vereinfachungsgewinn bei kleinstem Semantikrisiko. Ohne aktuellen Anlass ist der Eingriff unnötig.
Warum Stufe 2 gesperrtDer Phase-22-Plan warnt selbst: dynamische Abzweigungen machen eine Tabelle leicht unlesbarer als den heutigen Switch. Die Startbedingung „nextStep behindert die Wartung“ ist nach A–C nicht erfüllt.
Hammerdin und RoutenCountess, Mephisto, Summoner, Nihlathak und Cow bleiben produktive Verträge. Weitere Hammerdin-Fähigkeiten gehören in Profil/Combat, nicht in diese Datei.

6.5 Generator — einzige erlaubte Erzeugungsregel

// Pseudocode; Namen im Test dürfen abweichen, die Reihenfolge nicht.

func pipelineFor(phaseLabel string, flags flags) *runPipeline {
    phase := phaseLabel
    if phaseLabel == "full" { phase = "" }
    return &runPipeline{
        definition: RunDefinition{
            ClearNearbyAfterBoss: flags.clear == 1,
            ReturnOrigin:         originFor(flags.foreign),
        },
        phase: phase,
        travel: pipelineTravelState{
            resumeAfterPrecheckSet: flags.resume != "off",
            resumeAfterPrecheck:    resumeString(flags.resume),
        },
        boss: pipelineBossState{bossKillEmitted: flags.kill == 1},
        loot: pipelineLootState{lootScanHasTarget: flags.loot == 1},
    }
}

func encodeStep(step string) string {
    if step == "" { return "-" }
    return step
}

// Baseline: Phasen × Currents mit Null-Flags.
// Zeile: <phase>|<current>|<next>
for phase in Phasen {
    p := pipelineFor(phase, zeroFlags)
    for current in Currents {
        next := p.nextStep(decodeStep(current))
        emit("%s|%s|%s\n", phase, current, encodeStep(next))
    }
}

// Branches: jede Nicht-Null-Kombination, deren next ≠ Baseline derselben Phase/Current.
// Zeile: <phase>|<current>|<flag-string>|<next>
for phase in Phasen {
    for current in Currents {
        base := pipelineFor(phase, zeroFlags).nextStep(decodeStep(current))
        for flags in alle 2×2×2×2×3 Kombinationen in der Reihenfolge aus 6.4 {
            if flags == zeroFlags { continue }
            next := pipelineFor(phase, flags).nextStep(decodeStep(current))
            if next != base {
                emit("%s|%s|%s|%s\n", phase, current, flags.String(), encodeStep(next))
            }
        }
    }
}

Ziel

Identische Teilsequenzen aus nextStep als benannte Helfer ziehen. Keine Tabelle, kein neues Verhalten, kein Oracle-Doppel.

7.1 Startbedingung — mindestens eine muss zutreffen

  • Der Nutzer beauftragt ausdrücklich Stufe 1 umsetzen.
  • Eine geplante Topologieänderung müsste dieselbe Teilsequenz in einen zweiten Switch kopieren.

Stufe 0 muss grün und eingecheckt sein. Ohne Stufe 0 ist Stufe 1 verboten.

7.2 Erlaubte Helfer — und nur diese

Unexportierte Funktionen im selben Paket, ohne Receiver, in pipeline_flow.go. Jeder Helfer kennt nur current string und gibt den Nachfolger oder "" zurück. Keine Flags, keine Pipeline, keine Definition. Ein Helfer, der ein Flag bräuchte, ist die falsche Naht.

ReihenfolgeFunktionAbbildungAufrufer heute
1 nextSharedPortalReturn cast_town_portal → enter_town_portal → wait_origin_town Full Run, loot-and-return, retry-return
2 nextSharedForeignEgress play_town_egress → open_origin_waypoint → select_hub_waypoint → wait_hub_area dieselben drei Switches
3 nextSharedWaypointTravel acquire_town_waypoint → open_waypoint → select_run_waypoint → wait_entry_area Full Run und Travel-Phasen
4 nextSharedStash open_personal_stash → stash_items → close_personal_stash Full Run, loot-and-return, stash-personal

Beispielvertrag für Helfer 1:

// nextSharedPortalReturn returns the successor inside the shared
// town-portal subsequence. Unknown steps return "".
func nextSharedPortalReturn(current string) string {
    switch current {
    case pipelineStepCastTownPortal:
        return pipelineStepEnterTownPortal
    case pipelineStepEnterTownPortal:
        return pipelineStepWaitOriginTown
    default:
        return ""
    }
}

Kurzer Designkommentar am Helfer: warum die Sequenz geteilt wird und dass Branch-Punkte absichtlich draußen bleiben. Kein zeilenweises Kommentieren.

7.3 Was nicht extrahiert werden darf

  • scan_loot, wait_origin_town, wait_hub_area, close_personal_stash, precheck, acquire_boss, engage_boss — das sind Branch-Punkte oder phasenabhängig.
  • Kein Helfer, der nur an einer Stelle vorkommt.
  • Kein Helfer, dessen Nachfolger sich zwischen den Aufrufern in auch nur einem Step unterscheidet.
  • Kein Interface, kein Funktionsfeld, keine Tabelle von Kanten.

7.4 Änderungsdisziplin

  1. Genau ein Helfer pro abgeschlossener Änderung, in der Reihenfolge 1→4.
  2. Nach jedem Helfer die Stufe-0-Tests plus TestPhase22StandardPipelineGolden einmal ausführen.
  3. Alle drei neuen Goldens und das Phase-22-Golden müssen bytegleich bleiben. Ändert sich eine Zeile: Änderung verwerfen.
  4. Als Nächstes nur die unmittelbar betroffenen bestehenden nextStep-Tests in internal/tasks, nicht die Gesamtsuite.
  5. Zwischen zwei Helfern stoppen, wenn der Nutzer nicht „weiter mit Helfer N“ gesagt hat. Ein Auftrag Stufe 1 umsetzen erlaubt alle vier Helfer nacheinander, solange jeder Schritt grün ist.

7.5 Einbau in nextStep

In jedem betroffenen switch die identischen Arme durch den Helfer ersetzen. Der Branch-Arm bleibt lokal. Typisches Muster: 

case pipelineStepCastTownPortal, pipelineStepEnterTownPortal:
    return nextSharedPortalReturn(current)
case pipelineStepWaitOriginTown:
    if foreignTownOrigin(c.effectiveDefinition().ReturnOrigin) {
        return pipelineStepPlayTownEgress
    }
    return pipelineStepOpenStash

Wenn der Helfer "" für einen Step liefert, den der Switch noch behandeln muss, ist die Naht falsch — stoppen, nicht um einen Fallback ergänzen.

nextStep durch eine in Go deklarierte Kantenliste ersetzen, ohne YAML, ohne Bibliothek und ohne Handler-Umbau. Nur zulässig, wenn Stufe 0 grün ist und ein konkreter Topologieanlass den zentralen Switch nachweisbar aufbläht.

8.1 Anlass — einer muss schriftlich im Auftrag stehen

  • Eine neue isolierte Phase würde erneut 20–30 Switch-Zeilen kopieren.
  • Eine gemeinsame Teilsequenz muss in mehrere Phasen neu eingehängt werden und Stufe 1 reicht nicht.
  • Ein zweiter Run-Graph soll in der Standardpipeline leben, nicht nur ein neues Profil.

„Sieht eleganter aus“ oder „Stage D nachholen“ ist kein Anlass.

8.2 Erster Beweis, dann Rest

  1. Nur town-ready und stash-personal auf die Kantenliste heben. Das sind lineare Ketten ohne Flags.
  2. Lesbarkeitsgate: Ist die Tabelle länger, indirekter oder schwerer zu reviewen als der heutige Switch, Stufe 2 abbrechen und den Switch behalten. Das ist ein Erfolgskriterium, kein Scheitern.
  3. Erst nach bestandener Lesbarkeit: retry-return, dann loot-and-return, dann Full Run einschließlich not-a-phase-Fallthrough, dann Travel, dann Boss.
  4. Eine Phasenfamilie pro Änderung. Nach jeder Familie die Stufe-0-Goldens bytegleich.

8.3 Maximale Abstraktion

type transitionEdge struct {
    phase string // "" = Full Run; eine RunPhase*-Konstante; nicht "any"
    from  string
    to    string
    when  func(*runPipeline) bool // nil = immer
}
  • Eine feste Slice im Paket, keine Map als primäre Quelle (Maps sind ungeordnet und verdecken Reviews).
  • when darf nur die in Abschnitt 3 genannten Felder lesen.
  • Kein Match: Rückgabe "", wie der heutige default.
  • Mehrere passende Kanten: fail-closed in Tests; in Produktion darf das nicht vorkommen. Die Testdatei muss Doppelkanten hart ablehnen.

8.4 Oracle in Stufe 2 — nur dann

Erst wenn Stufe 2 wirklich läuft, darf die vorherige nextStep-Funktion als nextStepFrozen in der Testdatei liegen, nicht im Produktionspfad. Produktion ruft nur den neuen Resolver. Tests vergleichen für jede Generatorzelle aus Stufe 0: new(next) == frozen(next) == golden. Die eingefrorene Funktion darf nach dem Einfrieren nicht mehr angefasst werden, außer der Nutzer beauftragt eine bewusste Topologieänderung; dann müssen Frozen, Resolver und Golden in derselben Änderung gemeinsam angepasst werden.

Löschen von nextStepFrozen erst in einer späteren, eigenen Änderung, nachdem alle Familien migriert sind und mindestens eine echte spätere Topologieänderung nur noch den neuen Resolver getroffen hat.

8.5 Weiterhin verboten

  • Cow, Handler, Dispatcher-Semantik, Timings, Input.
  • YAML, JSON oder UI als Topologiequelle.
  • Stufe 2 als Voraussetzung für Hammerdin-Routen.
